概览

MiMo-Reasonix 是基于 DeepSeek-Reasonix Go 架构的品牌化重写，将小米 MiMo 模型（mimo-v2.5 系列）适配为默认后端，提供 CLI 编码 Agent 及 HTTP/SSE 服务。

项目继承原版 51 个内部包、约 607 个 Go 源文件（~177K 行），并新增 MiMo 专属的 Provider 层、配置适配、CLI 品牌化及 4 个自定义测试文件。二进制已成功静态编译（23MB），可独立运行。

发现的问题

CRITICAL · 文档站点未品牌化
docs/index.html 的 <title>、OG 标签、品牌名、链接均指向原始 DeepSeek-Reasonix（esengine/DeepSeek-Reasonix），而非 MiMo-Reasonix。对外展示存在品牌错误和链接死链风险。
CRITICAL · 自定义测试为 TDD 占位
tests/provider/mimo_provider_test.go 中 3 处 t.Skip（IsMiMo 检测、streaming 解析、tool call 组装均未验证）。
tests/cli/mimo_cli_test.go 中 3 处 t.Skip（二进制名、版本号、help 输出检查因路径问题跳过）。
测试文件存在但实际不执行 MiMo 行为验证，形同虚设。
CRITICAL · go.mod 声明不存在的 Go 版本
go.mod 声明 go 1.25.0 和 toolchain go1.26.4，当前 Go 最新稳定版为 1.24。这会导致 go install 和标准 CI 环境编译失败。
WARNING · Git 历史缺失
仅 1 个 "Initial commit"，所有文件均为 untracked 状态。项目缺乏可分步追溯的提交历史，不利于代码审查和问题定位。
WARNING · 内部测试覆盖不均
15 个包（包括 boot、agent 等关键路径）测试失败。部分因缺少 API 密钥，但也可能存在品牌化更新不彻底导致的测试断裂。
WARNING · 15 个包无测试文件
billing、doctor、environment、fileref、outputstyle、retrieval、sysproxy 等包缺少测试覆盖。
INFO · 配置命名不一致
README 提到项目本地配置为 ./mimo-reasonix.toml，而仓库中仅有 mimo-reasonix.example.toml。用户初次使用时可能对命名产生混淆。
